# Detect Agent：智能体运行环境识别规范

一份与编程语言无关的智能体运行环境识别规范。把文档交给智能体，它就能在你的项目中，
用现有语言和代码风格实现检测函数，无需安装 SDK，也无需运行时联网拉取规则。

**[阅读完整规范](detect-agent.md)** · [English](README.md) · [合成测试案例](conformance/cases.json)

## 直接交给智能体的提示词

```text
阅读本仓库的 detect-agent.md，在当前项目中实现其中的检测规范。
使用项目现有的语言和代码风格；保留文档规定的匹配语义、条件分组和优先级。
区分智能体运行标记与普通编辑器、工作区及配置提示。
使用合成环境验证文档示例及 conformance/cases.json，不读取本机实际环境做测试。
不要增加运行时联网依赖，不要记录环境变量的实际值。
```

## 内容

- 35 个统一产品 ID，以及明确的返回结果。
- 变量非空、固定值精确匹配、AND／OR 的具体语义。
- 优先级与兼容标记共存时的判定方法。
- QwenWork、Doubao Work 使用非空检测；Manus 与 Cue 分别识别。
- 将 Zed／Cursor 编辑器终端、Replit 工作区等标记作为上下文提示，避免直接宣称智能体在运行。
- 区分公开实现证据、发行包静态检查、用户 shell 观察与第三方注册表。
- 官方产品来源、已知覆盖边界，以及可移植的合成测试数据。

完整规范以英文维护，避免多个版本产生不同检测行为。可直接复制、附加或通过智能体自己的
工具读取 Markdown。建议固定到一个 Git commit，以便复现；更新副本前审阅规则变更。

这是规范仓库，不是 SDK。检测描述运行环境，不能证明当前命令由哪个智能体直接发起。
欢迎按 [贡献指南](CONTRIBUTING.md) 补充证据和规则。原创内容采用 [MIT](LICENSE) 许可。
